# TUN 功能使用指南

## ⚠️ 重要说明

TUN 模式是一个**高级功能**，可以接管系统所有流量，但需要特殊权限。

## 🔐 权限要求

### macOS

由于技术限制，TUN 模式需要管理员权限。

**方法 1: 终端启动（推荐）**

```bash
# 关闭当前应用后，在终端中运行：
sudo open -a xnetify
```

**方法 2: 直接运行**

```bash
# 关闭当前应用后，在终端中运行：
sudo /Applications/xnetify.app/Contents/MacOS/xnetify
```

**方法 3: 复制命令到剪贴板**

1. 在应用中尝试开启 TUN
2. 点击"复制命令"按钮
3. 在终端中粘贴并运行

### Linux

```bash
sudo ./xnetify
```

### Windows

1. 右键点击应用图标
2. 选择"以管理员身份运行"

## 💡 使用技巧

### macOS 用户

如果不想每次都输入密码：

1. 打开 **系统偏好设置** > **安全性与隐私**
2. 点击左下角的 🔒 解锁
3. 允许 "xnetify" 应用

这样只需要输入一次密码。

### Windows 用户

将应用固定到任务栏：

1. 右键任务栏图标
2. 右键 "xnetify"
3. 选择 "以管理员身份运行"
4. 以后双击任务栏图标就会以管理员身份启动

## 🔄 如果权限不够怎么办？

### 症状

尝试开启 TUN 时显示：
- "TUN 模式需要管理员权限"
- 或错误信息包含 "Permission denied"

### 解决方案

#### 方案 1: 使用系统代理模式

不需要特殊权限的替代方案：

1. 关闭 TUN 开关
2. 开启"系统代理"开关
3. 系统代理会自动配置浏览器和应用的网络设置

**优点**: 
- ✅ 不需要管理员权限
- ✅ 快速启用

**缺点**: 
- ❌ 只能代理浏览器流量
- ❌ 不能代理命令行工具

#### 方案 2: 以管理员权限运行

按照上面的说明，使用 sudo 重新启动应用。

## 📊 功能对比

| 功能 | TUN 模式 | 系统代理模式 |
|------|---------|------------|
| 代理所有流量 | ✅ | ❌ |
| 不需要权限 | ❌ | ✅ |
| 配置复杂度 | 中等 | 简单 |
| 速度 | 快 | 快 |
| 兼容性 | 好 | 依赖应用设置 |

## 🎯 什么时候用哪个？

### 使用 TUN 模式

- ✅ 需要代理所有应用的流量
- ✅ 需要代理命令行工具（如 curl、git、npm）
- ✅ 需要代理 Docker 容器流量
- ✅ 技术用户，有管理员权限

### 使用系统代理模式

- ✅ 普通用户，不想折腾
- ✅ 只需要代理浏览器
- ✅ 公司电脑，权限受限
- ✅ 临时使用

## 🔧 故障排除

### 权限足够但 TUN 仍然失败

可能的原因：

1. **设备被占用**
   - 重启应用
   - 检查是否有其他 VPN 应用

2. **IP 地址冲突**
   - 默认使用 `10.0.0.2`
   - 可能需要更换 IP 地址

3. **驱动问题**（macOS）
   ```bash
   # 检查 TUN 设备
   ls -la /dev/tun*
   
   # 如果不存在，创建：
   sudo mkdir -p /dev
   sudo mknod /dev/tun0 c 132 0
   sudo chmod 0666 /dev/tun0
   ```

### 日志查看

如果遇到问题，查看应用日志：

```bash
# macOS/Linux
# 应用启动时会显示日志

# 查看详细日志
sudo RUST_LOG=debug /Applications/xnetify.app/Contents/MacOS/xnetify
```
